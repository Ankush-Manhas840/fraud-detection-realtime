What an API is

Think of a restaurant. You never walk into the kitchen. You give your order to a waiter, the kitchen cooks it, and the waiter brings back your food.

An API is the waiter for a program. Other programs send it a request, it does the work, and it sends back an answer. They never need to know what happens inside.

Your fraud API

A purchase arrives→ Your API→ Model gives a score→ Answer: fraud or not 
Send:      {"amount": 450, "hour": 14, "outside_us": 1, ...}
Get back:  {"fraud_score": 0.87, "is_fraud": true}

Words you will meet

HTTPThe language programs use to talk over the web. Every request and answer follows its rules.
Request and responseThe request is the order you send. The response is what comes back.
EndpointOne address your API answers on, like /predict or /health.
GET and POSTGET asks for something. POST sends data to be processed, like a purchase to score.
JSONThe text format for sending data. It looks like a Python dictionary.
Status codeA number saying how it went: 200 fine, 404 not found, 422 bad input, 500 server error.
FastAPIThe Python library you use to build the API.
UvicornThe program that runs your API and keeps it listening for requests.
PydanticChecks that incoming data has the right fields and types, and rejects bad input automatically.
/docs pageA web page FastAPI makes for you, where you can try your API by clicking.

Check yourself

Answer out loud, without notes. These are common interview questions.

What is an API, in one sentence?

A way for one program to ask another for something and get an answer back, without knowing how the other works inside.

Why is /predict a POST and not a GET?

Because you send data (a purchase's features) to be processed. GET is for asking for something without sending a body of data.

What does Pydantic do for you?

It checks every incoming request has the right fields and types, and automatically answers with a 422 error if not, so bad data never reaches the model.

Why load the model once at start-up, not inside /predict?

Loading from disk is slow. Doing it once means each prediction only runs the model, which takes milliseconds.

What do status codes 200, 404, 422 and 500 mean?

200: it worked. 404: that address does not exist. 422: your input was wrong. 500: something broke inside the server.

How does your fraud API connect to the rest of the project?

The Kafka consumer builds each purchase's features from Redis, then sends them to /predict. The answer is logged and shown on the dashboard.
